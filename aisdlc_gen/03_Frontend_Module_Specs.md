# 03. 前端模組設計規格 (Frontend Module Specs)

**專案名稱**：小灶私廚 — 訂單管理系統
**最近更新**：動態成本計算（百分比轉換）與 UI 響應修正

## 一、訂單建立 (`OrderNew`)
- **動態表單**：透過 `App.getMenu()` 將最新菜單與其單價帶入下拉挑選區塊。
- **即時試算**：小計與總額隨時更新，並且對於無單價（例如：`1.4*重量`）將略過小計，以空白讓用戶日後於排單中重新填列。
- **並發分流寫入**：按下儲存後，主單 (UUID) 與每一列排單 (獨立 UUIDS) 透過 Promise.all 併發送往 GAS 端點。

## 二、排單管理 (`OrderList`)
- **雙重視角設計**：上方保留總體排程概覽與條件過濾；點擊「查看明細」可帶出特定訂單的修改對話方塊。
- **狀態與金額更動機制**：在明細表上勾選不同的排程狀態，或調整實際的秤重金額（小計欄位）。
- **防呆連鎖刪除機制**：當使用者在管理區「刪除了某一筆訂單的唯一一項明細」時，前端將連動一併觸發批次刪除該明細對應的**訂單主檔**，防止孤兒空單（Ghost Orders）佔據主檔。
- **跑版修復**：彈性排版 (`flex`) 外放至 `div` 容器而不用在 `td` 原生物件上，杜絕底線對齊不一之問題。

## 三、營收統計分析 (`Revenue`)
此模組經歷了深度的重構已成為財報之核心引擎：

- **時間區間抓取**：篩選後，會利用訂單的成立時間去擷取出有效的排單清單。
- **超級字串除塵器 (Trim Helper)**：對於從表格中拿出的每個欄位名稱甚至字串數值，全面導入防呆清理過濾，不論是 `訂購數量 ` 或是 ` 涼拌小菜` 都能被完美校正與匹配。
- **智能「動態 / 靜態預估成本」演算法**：
  若該菜品的成本設定具備百分比標記（如 `45%`）：程式將**不去死背原本的單價**，而是拿排單表最後實際產生的「總小計金額」，即時乘上 `45%` 作為該品項總成本。這徹底攻克了「秤重品項因每顆重量不同，但固定成本下算錯毛利」的不準確問題。
  反之，如果是絕對數值（如 `90`），系統將保留傳統數量演算法 (`90 * 購買數`)。

## 四、支出與菜單維護 (`Expense`, `MenuMgmt`)
- 全面汰除針對 Row Index 的行數鎖定刪除。
- 現行版本所有編輯與歷史紀錄移除，皆改以「定位隱藏 ID」方式打入 GAS 的批回饋端。
- 分為 `toAppend` (準備新增)、`toUpdate` (準備蓋換舊資料) 等不同快取暫存區列，再一次性透過 Promise 包裝觸發，創造流暢無比的 UX。
