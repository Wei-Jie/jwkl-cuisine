# 02. 資料與 API 結構規劃 (Database & API Schema)

**專案名稱**：小灶私廚 — 訂單管理系統
**最近更新**：UUID 重構機制與 GAS 端點 Batch 批次操作

## 一、Google Sheets 作為資料庫 (Database Design)

所有的資料表均以 Google Sheets 中的分頁來實作，為了確保前端的存取穩定性，每一份表單的「第一欄」已全面確立為全域唯一識別碼（`ID`）。

### 1. 訂單主檔 (Order Main)
紀錄整筆訂單的大寫輪廓與摘要：
- **ID (UUID)**：唯一識別碼 (Primary Key)。
- **訂單編號**：易讀性代碼（如 240328-1150）。
- **訂單日期**：建立日期。
- **訂單金額**：本單所有明細之加總。
- **顧客名稱**：買家名稱。
- **收款日期**：若不為空字串，系統視為「已收款」，並列入相關統計。

### 2. 排單表 (Schedule)
核心明細表庫，紀錄訂單內各種細項的處理排程：
- **ID (UUID)**：明細層的唯一碼。
- **訂單編號**：對應主擋（Foreign Key）。
- **訂單日期、客戶名稱**：從主檔帶入之重疊備查資訊。
- **品項**：從菜單挑選的正確菜名。
- **預計出貨日期 (A)**：手動押入時間。
- **數量** 或 **訂購數量**：單品數量。
- **商品單價**：固定值或含有浮動文字（如 1.4*重量）。
- **小計價格**：此特定細項被認定或秤重後的總收取金額。
- **排程狀態**：目前狀態區間（未處理, 製作中, 已完成, 已出貨）。

### 3. 菜單 (Menu)
- **ID、分類、菜名、單價**。
- **預估成本**：支援百分比（如 `40%`）或整數（如 `150`），營收統計算法現已全面支援。

### 4. 支出紀錄 (Expenses)
- **ID、日期、分類、項目說明、金額、備註**。

## 二、GAS 中介 API 的操作介面 (API Interface)

端點 `Backend.gs` 提供單一進口，以 POST 請求並帶入 JSON Body 的 `action` 來區分動作類型：

#### ⭕ 全域指令與批次作業 (Batch Operations)
- **GET_SHEET**：取得整個分頁資料。
- **APPEND_ROWS**：寫入新列數。
- **UPDATE_BY_ID**：在該分頁內匹配 ID 並取代整列資料。
- **BATCH_UPDATE_BY_ID**：傳入多筆含有 ID 與 newData 的物件陣列，GAS 端批次更新數筆資料提速。
- **BATCH_DELETE_BY_ID**：傳入 UUID 的字串陣列，批次在分頁內尋找並一次性刪除，徹底杜絕逐筆刪除之網路延遲。

## 三、前端資料庫交互模組 (Sheets.js)

為了遮蔽後端發送 HTTP POST 與 GAS 解碼的複雜度，前端統一經由 `Sheets.js` 中封裝的操作。
- **資料清洗 (rowsToObjects)**：將二維 Google Sheets 矩陣映射回帶有 Header 屬性的標準 JSON Object 陣列，簡化查找業務邏輯。
- **並發處理**：大量呼叫端點時轉交 `Promise.all` 等待統一回報。
