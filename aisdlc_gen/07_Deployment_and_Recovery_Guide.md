# 07. 系統部署、營運與還原指南 (Deployment & Recovery Guide)

**文件狀態**：v2.0
**對應環境**：Google Apps Script (GAS) Web App + 試算表資料庫

---

## 1. 部署作業 (Deployment Steps)

### 1.1 GAS 後端部署
若需更新或遷移 `Backend.gs` 的代碼：
1. 開啟目標 Google 試算表。
2. 點擊功能表「擴充功能」>「Apps Script」。
3. 貼上最新的 `Backend.gs` 內容。
4. **重要步驟**：點擊右上角「**部署**」>「**新建部署**」。
5. 選取「網頁應用程式」，設定：
   - 說明：JWKL_v2.0_Update
   - 執行身份：我 (您的 Google 帳戶)
   - 誰可以存取：所有人 (Anyone)
6. 複製彈窗產生的 **Web App URL**。
7. 回到前端 `js/config.js` 貼上該 URL。

### 1.2 前端發布
- 將整個資料夾上傳至靜態代管空間（如 GitHub Pages）。
- **快取強制更新**：若有新版腳本，請手動修改 `index.html` 下方 `<script src="js/xxx.js?v=N">` 中的 `v=N` 版本號。

## 2. 還原機制與安全防範 (Recovery Control)

當資料不慎誤修或代碼出錯時，請依照下列步驟恢復系統。

### 2.1 試算表資料還原 (Data Recovery)
由於試算表為此系統之唯一資料庫，Google 提供了強大的版本控制：
1. 開啟 Google 試算表。
2. 點擊上方「檔案」>「版本紀錄」>「查看版本紀錄」。
3. 從右側時間軸挑選欲還原的時間點（例：1 小時前）。
4. 點擊「**還原成這個版本**」即可瞬間救回誤刪之資料。

### 2.2 GAS 代碼版本回滾 (Code Rollback)
如果修改了 `Backend.gs` 卻導致 API 壞掉：
1. 在 Apps Script 介面中，點擊「部署」>「管理部署」。
2. 從左側挑選先前狀態正常的「**版本名稱**」。
3. 重新選取並點擊「部署」即可回滾至舊版穩定代碼。

### 2.3 建議之備份與預警機制 (Suggested Backup)
- **定期複製備份**：每週定時將整份試算表「建立複本」，並存檔為「小灶私廚_Bak_2024WWN」。
- **建立「備份存檔」分頁器**：
  建議每年年底建立一個如「訂單_2024結案」之分頁。
  將舊年度資料「剪下」並「貼上」至該分頁，維持主表的輕量化（建議主表維持在 5000 列以內）。

## 3. 常見問題排除 (Troubleshooting)

| 出現現象 | 可能原因 | 解決對策 |
|----------|----------|----------|
| 資料不變 | 瀏覽器載入舊版快取 | 按下 `Ctrl + F5` 強制重整。 |
| 轉圈圈不停 | GAS URL 錯誤或配額用盡 | 檢查 `config.js` 與 Google 限額。 |
| 毛利顯示 "-" | 品項名稱不一致 | 檢查菜單品項名稱與訂單明細之名稱是否完全相同。 |
| 權限錯誤碼 | 試算表存取權未開 | 確保 GAS 執行身份有該試算表的編輯權限。 |
